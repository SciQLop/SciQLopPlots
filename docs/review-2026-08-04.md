# SciQLopPlots code review — 2026-08-04

Six parallel review passes over `src/`, `include/`, `SciQLopPlots/` (Python layer + Shiboken
bindings). NeoQCP out of scope except where SciQLopPlots calls it wrongly. Main use case kept in
mind: driven from Python inside SciQLop (GIL, worker-thread resamplers, panning large time series
and spectrograms). ⚡ = found independently by two reviewers.

## Critical

1. ⚡ **`dsp.reduce_axes`: out-of-bounds heap write from Python.**
   `src/DSP/python_module.cpp:1384-1397` casts `PyLong_AsLong` results to `std::size_t` with no
   error/range check; `ReduceAxesSpec` then does `is_red[axes[i]] = true` on a `vector<bool>` of
   size `ndim` (`include/SciQLopPlots/DSP/Reduce.hpp:157-159`). `axes=(5,)` or negative axes
   (`-1` → huge `size_t`) → heap corruption. Negative `shape` values wrap mod 2^64, can pass the
   `prod == ncols` check → OOB reads. Unchecked `PyLong_AsLong` errors also silently absorb `-1`.
   Fix: check `PyErr_Occurred()` after each conversion; reject `axis >= ndim` (map negatives
   numpy-style) and `dim <= 0`; guard `prod` overflow.

2. ⚡ **`SciQLopCurve` silently garbles C-order (n, k) 2D `y`.**
   `src/SciQLopCurveResampler.cpp:67-71` reads component i as `ys + i*count` (column-major
   assumption); `src/SciQLopCurve.cpp:121-130` validates only `flat_size`. `np.column_stack(...)`
   renders fine on `LineGraph` (`SciQLopMultiGraphBase::build_data_source` handles both layouts,
   `src/SciQLopMultiGraphBase.cpp:81-98`) but interleaved/garbled on `ParametricCurve`. ColorMap
   rejects non-row-major (`src/SciQLopColorMap.cpp:121-128`); curve never got the same guard.
   Fix: reject non-row-major 2D y in `SciQLopCurve::set_data`, or pass stride to the resampler.

3. **UAF: committed score hashes keep dangling `ProductsModelNode*`.**
   `src/ProductsTreeFilterModel.cpp:294-353` (`remerge_committed`, `apply_cutoff_and_coverage`,
   `set_max_score_tiers`). Re-publish deletes old node (`src/ProductsModel.cpp:59-62`);
   `start_scoring()` clears only pending hashes; committed `m_node_scores`/`m_node_raw_signals`
   key on freed pointers for 39+ event-loop ticks. Any `set_score_merge_strategy()` /
   `set_signal_weight()` / `set_override_signal()` / `set_max_score_tiers()` in that window →
   `it.key()->parent_node()` on freed memory (line 349) → crash.
   Fix: purge removed subtree pointers on `rowsAboutToBeRemoved`, or key by
   `QPointer<ProductsModelNode>` and skip null keys.

4. ⚡ **`SciQLopCurve` busy flag stuck forever on empty/invalid data or failing callable.**
   `src/SciQLopCurve.cpp:131` sets busy unconditionally; `CurveResampler::_resample_impl`
   early-returns without emitting `setGraphData` when x invalid/empty
   (`src/SciQLopCurveResampler.cpp:42-50`); `set_busy(false)` only lives in `_setCurveData`.
   For `SciQLopCurveFunction` the ctor disconnects the `pipeline_idle` fallback
   (`src/SciQLopCurve.cpp:274`), so a raising Python callable leaves the activity marker spinning
   forever and `remote_busy()` stuck.
   Fix: always emit (even empty batch) from `_resample_impl`, or skip `set_busy(true)` when
   input invalid/empty.

## High

5. **`ObservableProperty.value` splats any list/tuple — breaks `offsets`.**
   `SciQLopPlots/properties.py:74-81`: `setattr` splats `(*val)`. Right for `data`
   (`set_data(x, y)`), wrong for `set_offsets(QVector<double>)` (`__init__.py:218-223`,
   `SciQLopWaterfallGraph.hpp:53`). `wf.on.offsets.value = [0.,1.,4.]` → TypeError;
   `wf1.on.offsets >> wf2.on.offsets` dies with unraisable slot error (slot catches only
   RuntimeError, `pipeline.py:70-72`).
   Fix: splat only for `property_type == "data"` (or explicit `splat=True` in the spec).

6. **Pipelines silently die when the shiboken wrapper is GC'd.**
   `properties.py:44` weak-refs the Python wrapper; C++ doesn't pin it. Fluent style
   `plot.x_axis().on.range >> sink` drops the last strong ref immediately → weakref None →
   `RuntimeError` swallowed by `_make_dispatch` → connection attached forever, pipeline a silent
   no-op. Tests pass only because they hold strong refs.
   Fix: hold a strong ref in `ObservableProperty`, or at minimum warn instead of silent pass.

7. **FFT/spectrogram on int32 data returns all zeros.**
   `include/SciQLopPlots/DSP/FFT.hpp:91`, `Spectrogram.hpp:99`: `make_window<T>` uses the *data*
   dtype; window coefficients in [0,1] truncate to 0 in int32; `python_module.cpp:138-145`
   explicitly accepts `NPY_INT32`. Fix: always `make_window<double>`; `fft_column` /
   `power_spectrum` take `const double* window`.

8. **`SciQLopPlotInterface::resized()` never emitted.**
   Declared `SciQLopPlotInterface.hpp:535`; connected by
   `SciQLopNDProjectionPlot::set_equal_aspect_ratio` (`src/SciQLopNDProjectionPlot.cpp:130`);
   impl emits `resized(QSize)` (`src/SciQLopPlot.cpp:480`) but the wrapper ctor never forwards it
   (`src/SciQLopPlot.cpp:701-719`). Equal-aspect enforced only once at enable time.
   Fix: forward the signal in the `SciQLopPlot` ctor.

9. **Division by zero in `organize_plots()` on empty container.**
   `src/SciQLopPlotContainer.cpp:217-224`: `sizes()` empty → `total_height / 0` (SIGFPE).
   Reachable: press `O` on a panel with no plots (`SciQLopMultiPlotPanel.cpp:488-490`).
   Fix: early-return on empty.

10. **`MultiPlotsVerticalSpan` null-deref after direct plot destruction.**
    `src/SciQLopMultiPlotObject.cpp:64-67` requires `!plot.isNull()` → destroyed plots never
    purged from `m_plots`; `src/MultiPlotsVSpan.cpp:28-106` loops span setters with no null
    check; per-plot span wrappers are children of the plot → null entries in `_spans` →
    segfault on next `set_range()`/`set_color()`.
    Fix: purge nulls in `updatePlotList`; guard loops with `if (span)`.

11. **MultiGraph component-count shrink leaves stale wrappers → OOB.**
    `QCPMultiGraph::syncComponentCount()` shrinks `mComponents`; `component(int)` is unchecked
    (`plottable-multigraph.h:75-76`). `SciQLopMultiGraphBase::sync_components`
    (`src/SciQLopMultiGraphBase.cpp:104-120`) only adds wrappers, never removes → wrapper ops
    (`set_pen`/`set_visible`/`color()` in `src/SciQLopGraphComponent.cpp`) index OOB.
    Fix: delete trailing wrappers on shrink; bounds-check `m_componentIndex` defensively.

12. **Products ingest is O(N²).**
    Every `add_node` (per product) triggers flat-model full `rebuild()` (`beginResetModel` +
    `collect_all_leaves` + string building, `ProductsFlatFilterModel.cpp:21-24,111-138`) and tree
    rescoring; completer copies whole `stringList()` + linear `contains()` per node.
    Fix: batch-ingest API deferring rebuilds; completer via `QSet` + append-only.

13. **Per-keystroke synchronous corpus walk with string building on UI thread.**
    `set_query()` → `rebuild()` builds `path_text`/`meta_text` for every leaf synchronously
    (`ProductsFlatFilterModel.cpp:111-138`; `path()` is O(depth) allocations per call,
    `ProductsNode.cpp:73-83`). 77k-leaf corpus → UI stall per debounced keystroke.
    Fix: cache path text per node, or build strings inside the parallel pass.

14. **Full-corpus scoring pass even when query is empty.**
    `ProductsView.cpp:121-126` calls `set_query` unconditionally; empty query → flat model inserts
    all 77k leaves, tree model scores everything — the most expensive operation happens exactly
    when nothing is searched.
    Fix: early-out both models when tokens+filters empty.

36. **Range-fetch debounce starves under continuous pan.** `DataProducer.cpp:156-167` restarts

37. **`parallel_for` waits on the whole process pool.** `Parallel.hpp:68-69` `pool().wait()`

38. **Per-release `Py_AddPendingCall` churn.** `PythonInterface.cpp:156-179`: schedule only on
    empty→non-empty transition; 32-slot ring silently drops when full.

## Review of the fix batch — 2026-08-05

### R1 (critical, regression introduced by the batch itself)

**Fix 12 re-opened finding 3 in the flat model.** Coalescing the flat model's
`rebuild()` onto a 0 ms timer (`526d274`) meant `m_results` / `m_pending_leaves` kept raw
`ProductsModelNode*` across the removal — and `ProductsModel::_insert_node` deletes the
replaced subtree immediately after `endRemoveRows()`. Reading any row before the next
event-loop turn dereferenced freed memory: **deterministic SIGSEGV on a plain build**, no
ASan or `MALLOC_PERTURB_` needed, from the ordinary "re-publish a same-named product"
sequence SciQLop performs routinely.

Fixed by splitting `rebuild()` into `drop_results()` (pointer-dropping, cheap) +
re-collection, and running `drop_results()` synchronously on `rowsAboutToBeRemoved` /
`modelAboutToBeReset` while the nodes are still alive. Inserts keep the coalescing.
Reproducer: `test_products_filter.py::TestFlatFilterRepublishUaf` (segfaults pre-fix).

### Also fixed

- Finding 9 (`organize_plots` div-by-zero) — see the table above.
- Finding 11 follow-up: the shrink path deleted component wrappers without emitting
  `component_list_changed()`, which the grow path emits via `_register_component`; anything
  rebuilding from `components()` (the inspector tree) kept the stale list.
  Test: `test_graph_api.py::test_shrinking_columns_notifies_component_list`.
- Finding 5 follow-up: the `try setter(val) / except TypeError: setter(*val)` probe is
  replaced by an explicit `splat` flag in the property spec (`splat=True` on `data` and on
  the axis `range`, whose `set_range(start, stop)` is multi-arg — the span's
  `set_range(range)` is not). The probe would have silently re-invoked a Python setter that
  raised `TypeError` internally.

### Standing caveat on fix 12

The coalescing is per event-loop turn, so it only collapses a *synchronous* ingest loop
(what `test_products_ingest_perf.py` measures). Products ingested from async provider
callbacks — one event-loop turn each — still pay one full corpus walk per product, i.e. the
O(N²) of finding 12 remains on that path. A real batch-ingest API is still the fix.
